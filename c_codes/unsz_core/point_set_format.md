# UNSZ点集格式

不使用`-point-set-config`时全部数据属于唯一点集，EB来自必须显式提供的命令行`-M`。`-M`和`-point-set-config <JSON路径>`必须且只能选择一个。使用`-point-set-config`时，配置文件定义一个或两个点集；所有`method="predict"`的点集统一使用内置RBF。

`labels`数组按优先级保存点集。除最后一个label外，每项都包含`method`、`eb_mode`、`eb_value`和`condition`；第一条成立的条件决定点集编号，全部不成立时属于最后一个label。`method`只能是`predict`或`constant`。最后一个label省略`condition`，`constant`还省略`eb_mode`和`eb_value`。比较符支持`<`、`<=`、`>`、`>=`、`==`和`!=`。只有一个label时也不写`condition`。点集分类只读取当前field的数值，不接受额外标签文件。

同一文件中的每个点集独立统计点数和值域，只在同点集的已重建点之间执行数值预测。所有非常量点集统一使用固定10点Exponential RBF，并分别配置自己的REL或ABS EB。常量点集不配置EB，也不保存量化索引。RBF固定使用0阶常数趋势；完整参考集合的权重在预处理时计算并跨time step复用。参考点不全属于目标点集时退化到最近的同类参考点，没有同类参考点时预测为0。

## 二分类标签通道

两个点集使用一条二分类标签通道。程序预测每个点属于点集1还是点集2，并只保存0=预测正确、1=预测错误的修正bit。两个点集是对等类别，存储方式不依赖哪个点集占多数。每个预测结构在自己的目标顺序内只保存值1位置的差分，再使用Zstd level 3压缩。每个time step独立生成标签，因此同一空间点的类型可以随time step变化。单点集数据没有标签通道。

## 容器版本

当前压缩器只写v15格式，解压器也只读取v15。v15固定使用10点Exponential RBF，并统一使用float执行预测、EB缩放、量化和重构。公共文件头保存magic、版本、点数、数据类型字节数、最终选择的label/value flow、每个点集的codec、点数和值域，随后保存预测结构数量和`payload_begin[P+1]`相对偏移表。记录最终flow后，使用`auto`的解压端可以直接恢复压缩端选中的流程，不需要重新执行自动选择。单线程是不分区的一个预测结构，因此同样写一个payload，不存在另一套串行格式。每个预测结构的payload独立保存：

1. 每个条件标签通道的目标数量，以及错误位置差分后的独立Zstd frame；
2. 每个点集的量化索引数量，以及独立Huffman编码后再独立Zstd得到的frame；
3. 按量化索引中`INT32_MIN`哨兵的出现顺序连续保存不可预测点的原始值，不另存数量字段。

不同预测结构之间不共享预测参考、Huffman树或Zstd frame，因此多个空间partition的压缩和解压可以并行执行。偏移使用`uint64_t`，payload按照预测结构编号顺序拼接；解压时仍需提供和压缩时相同的partition划分参数。

数值codec写入容器，但相对或绝对误差上限仍不写入。使用JSON时压缩器和解压器必须使用相同配置；不使用JSON的单点集模式则必须在两端通过`-M REL <eb>`或`-M ABS <eb>`提供相同参数。REL模式始终根据对应点集自己的最大值和最小值换算ABS EB。

预测DAG仍由外部坐标重建。RBF、DAG和EB schedule使用程序内固定参数；partition参数、坐标变换结果和误差参数不保存在文件中，压缩和解压时必须保持一致。
